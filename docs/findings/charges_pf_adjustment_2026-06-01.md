Re-prices every trade in every locally-available battery results JSON using the AngelOne-corrected charges model (CHG-01..CHG-05 — see `docs/findings/findings_log_2026-06-01.md`). The original JSONs are **not modified**; this is a transparent post-hoc adjustment.

**Methodology:**

1. For each trade we recompute `compute_round_trip(buy, sell, qty, product)` under the new AngelOne defaults.
2. `extra_charges = correct_charges − original_commission`
3. `adjusted_pnl = original_pnl − extra_charges`
4. PF is recomputed from the adjusted per-trade PnLs as `Σ(adj_pnl>0) / |Σ(adj_pnl<0)|`.
5. Trades that flip from winner to loser (or vice-versa) are counted.

**What this number is NOT:** a re-simulated backtest. The simulator's position-sizing, gate-firing, ensemble vote, etc. would all be different if it had been priced correctly. A full re-run would likely show fewer trades (more rejected at the reward_vs_charges gate) and somewhat different per-trade outcomes. Treat the numbers below as a **lower bound on the optimistic bias** — a re-simulation would almost certainly tighten PF further on the v3 swing variants.
